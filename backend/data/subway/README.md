# 수도권 지하철 네트워크 데이터

1단계 이동시간 추정(API 호출 없음)에 쓰는 지하철 그래프입니다. 생성된 `network.json`을 `app/subway.py`가 읽습니다.

## 출처

| 데이터 | 출처 | 라이선스 |
|---|---|---|
| 1~8호선(서울교통공사 운영 구간)의 역 순서와 **역간 소요시간** | [서울 열린데이터광장 · 서울교통공사 역간거리 및 소요시간](https://data.seoul.go.kr/dataList/OA-12034/F/1/datasetView.do) 파일 `서울교통공사 역간거리 및 소요시간_240810.csv` (수정일 2024.09.02, 기준 2024.3.25) | 공공누리 1유형 (출처표시, 상업적 이용·변경 가능) |
| 역 **좌표** | 카카오 로컬 API 키워드 검색(지하철역 `SW8`) 결과 (`scripts/build_subway_network.py`가 조회, `_coord_cache.json`에 캐시) | 카카오 API 이용약관 |
| 1~8호선 외 노선·구간의 **역 순서** | 노선도 기준으로 직접 입력 (`extra_lines.yaml`) | - (직접 작성) |

원본 CSV는 `seoul_metro_intervals_240810.csv`로 UTF-8 변환만 해서 그대로 두었습니다. 원본은 서울교통공사 구간만 포함하므로
코레일 구간(1·3·4호선 일부), 9호선, 수인분당선, 신분당선, 경의중앙선, 공항철도, 경춘선, 우이신설선, 신림선은 `extra_lines.yaml`로 보충했습니다.

## 소요시간을 만드는 방법

- **공식 구간 (간선의 약 47%)**: CSV의 운행시간을 그대로 씁니다. CSV는 노선마다 역을 한 줄로 이어 놓아서 분기·순환 구간은 `rules.yaml`의 `official_breaks`로 연결을 바로잡았습니다 (2호선 성수·신정 지선, 5호선 마천 방면).
- **추정 구간 (간선의 약 53%)**: 공식 시간이 없는 구간은 공식 구간 약 270개로 최소제곱 적합한 식 `분 = a + b × 거리(km)`로 추정합니다 (a≈0.39, b≈1.0, 평균절대오차 0.21분). 거리는 두 역 직선거리 × 1.1(선로 굴곡). 속도가 빠른 노선(신분당선, 공항철도 등)은 `rules.yaml`의 `factor`로 시간을 줄였습니다.
- **환승**: 같은 역명이면서 두 노선 노드가 450m 이내일 때만 환승 간선을 만듭니다 (신촌 2호선과 경의중앙선처럼 멀리 떨어진 같은 이름은 제외). 환승 시간은 기본 4분이고 큰 환승역은 `rules.yaml`에서 따로 정했습니다.
- 급행·직통 열차, 배차 간격, 실제 도보 환승 거리는 반영하지 않습니다. 이 그래프는 후보 지역을 가려내는 용도이고, 상위 3곳은 경로 API의 실제 소요시간으로 다시 계산합니다.

## 한계

- 역 순서(`extra_lines.yaml`)는 노선도를 보고 직접 입력해서 오류가 있을 수 있습니다. 카카오 검색에서 노선·역명이 확인된 역만 그래프에 들어갑니다.
- 카카오 검색에서 찾지 못한 역(4호선 당고개, 경의중앙선 화전)은 제외하고 앞뒤 역을 직접 이었습니다.
- 1단계 추정과 Google 실제값의 차이는 추천을 실행할 때마다 로그에 남고 응답의 `meta.estimate_accuracy`에도 들어갑니다. 2026-10-15 기준 홍대입구·잠실 → 상위 3곳 6건의 평균절대오차는 1.2분이었습니다.

## 다시 만들기

```bash
cd backend
python scripts/build_subway_network.py
```

`seoul_metro_intervals_240810.csv`, `extra_lines.yaml`, `rules.yaml`을 고친 뒤 실행하면 `network.json`이 다시 만들어집니다.
역 좌표는 `_coord_cache.json`에 캐시되어 있어 새 역을 추가하지 않으면 카카오 API를 다시 호출하지 않습니다.
